# 工程稳定性优化（2026-10-30）

本次处理启动、关闭、构建和备份恢复中的可复现故障，共 7 项。没有增加依赖，也没有修改业务数据格式。

| 问题 | 修复及回归依据 |
| --- | --- |
| 就绪请求取消后，存储探针仍在线程内执行，应用却可能先关闭数据库连接池 | 正常关闭时等待共享探针完成，再关闭研究任务和存储；测试覆盖探针成功、失败以及请求已取消的情况。 |
| 备份清单是合法 JSON、但字段结构错误时，校验抛出未处理的类型异常 | 在读入内容后先检查格式版本、项目名、哈希字典和数据库计数；恢复在启动 Docker 前明确拒绝损坏清单。 |
| 备份文件被替换为 FIFO 等特殊文件时，校验可能阻塞 | 打开前要求目录内三个备份文件均为普通文件，继续拒绝符号链接。 |
| 备份已捕获完整，但在重启 API 时按 Ctrl-C，临时目录被清理，完整副本丢失 | 完成校验并发布备份后再传播中断；已有失败重启的保留行为继续适用。 |
| DOCX 的 UTF-16 XML 可绕过按 ASCII 字节检查的实体声明拒绝规则 | 在 XML 解析器的 doctype 回调中拒绝 DTD；UTF-8、UTF-16、LE、BE 实体样例均被拒绝，普通 UTF-16 文档仍可导入。 |
| `uv --frozen` 会在依赖声明变更后继续安装旧锁文件 | CI 和镜像构建改用 `--locked`。临时清单将 `httpx` 要求改为 `>=99` 时，旧命令退出 0，新命令退出 1；正常项目检查通过，锁文件内容未变化。 |
| 容器启动或重建期间，截断的 HTTP 响应使部署检查立即退出 | 就绪探针重试 `HTTPException`；本地 HTTP 服务器先发截断 chunked 响应、再发健康响应的端到端测试通过。后续功能断言仍严格失败。 |
