# BreathOn使用手册

适用架构：React + Tauri 2 Android 用户端，服务器 Web 管理端及后端服务。

Android App 用于练习、学习和查看个人记录；管理员通过服务器 `/admin` 准备训练内容和审核资料。下文的内容管理与服务设置操作仅适用于 Web 管理端。

账号由管理员预配置，不提供公开注册。App 使用服务器账号登录，个人演练和拜访记录按账号隔离；管理员可通过管理接口访问代表记录并留存审计。请使用虚构或充分脱敏的训练内容，不要输入真实患者身份信息。AI 反馈用于练习参考，医学内容须由专业人员复核。

## 快速完成第一次练习

1. 安装 [Android APK](android.md)，打开 App，使用已有账号登录服务器。
2. 在「练习」选择自由练习，分别选择已发布药品和模拟医生；需要量表评分时选择已发布的评分场景。
3. 选择「辅助练习」或「实战练习」，确认完整组合或场景与资料版本。
4. 点击「开始练习」，允许 App 使用麦克风，等待医生开场后口述回答。
5. 点击「结束演练」，等待最终转录、复盘和保存确认。
6. 进入「我的 → 复盘记录」，检查原话、反馈和资料引用。

自由组合不评分。没有已发布药品、医生或场景时，需由管理员在 Web 管理端核对并发布后使用。

## 页面入口

App 底部只有三个标签：

| 入口 | 主要用途 |
| --- | --- |
| 练习 | 选择药品、医生、场景和演练方式，开始或返回当前演练 |
| 学习 | 查阅药品、医学依据、医生、政策和技能资料 |
| 我的 | 显示当前账号、退出登录，进入拜访日记和复盘记录 |

拜访日记、复盘列表返回「我的」，详情先返回所属列表。管理员的内容维护、审核与服务设置只在 Web 管理端提供，App 中没有后台入口。

切换 App 标签不会中断当前演练。强制停止 App、退出账号或停止后端会影响会话；结束后应先确认保存。演练进行中或保存未确认时，退出登录不可用。

## 选择演练方式与训练环节

### 两种演练方式

| 方式 | 对话体验 | 教练反馈 |
| --- | --- | --- |
| 辅助练习 | 口述回答，医生以语音和文字回复 | 对话中提供实时建议，结束后复盘 |
| 实战练习 | 双向语音交流，可随时打断医生 | 结束后统一复盘 |

两种方式均使用麦克风。自由组合不提供场景量表评分；绑定已发布场景后，才按该场景的有效资料和量表评价。

### 完整拜访与单环节练习

选择场景后，展开「训练环节」：保留「完整拜访」，或选择该场景包含的开场、需求探询、研究介绍、异议处理、安全沟通、收尾等环节。

开始前确认本轮目标。只练一个环节时，其他未发生的行为可能显示「未观察」，不应把它理解为零分。

### 演练中的操作

| 操作 | 使用说明 |
| --- | --- |
| 场景说明 | 查看模拟医生背景、训练目标和本轮资料版本 |
| 静音／取消静音 | 暂停或恢复麦克风输入；静音不会结束演练 |
| 打断 | 实战演练中停止医生当前回复，继续表达自己的问题；也支持直接说话打断 |
| 结束演练 | 结束交流并进入最终转录、分析和保存流程 |
| 查看复盘 | 演练结束后查看本次反馈 |

练习时尽量在安静环境使用耳机，避免外放声音被麦克风再次采集。转录中的文字会继续修正，请以最终记录为准。练习模式中，新发言可能取消尚未完成的旧回复或朗读。

医生文字生成失败和医生朗读失败是两种情况：按页面提示分别重试。仅朗读失败时，已有文字和教练建议仍可阅读，无需为了听语音重新生成整轮内容。

练习模式的医生朗读会沿用医生配置中的「中性／忙碌／质疑／友好」互动状态，并根据台词语义自然调整语气；「时间紧张」场景优先采用紧凑节奏。开场、后续回应和重试朗读使用同一训练设定；未选择场景时使用平和语气。这些情绪是虚构训练设计，不代表真实医生的情绪，也不用于评价学员情绪。

语气控制使用豆包 TTS 2.0 的 [context_texts 语音指令](https://docs.volcengine.com/docs/doubao-voice/websocket-bidirectional-streaming-v3?lang=zh)。默认云舟 2.0 支持指令遵循；更换 `DOUBAO_TTS_VOICE` 时请核对官方音色能力。实际表现随音色和台词变化，需听感验收。

单次演练默认最多 10 分钟。结束后不要立即刷新：实战模式还需等待最终转录和整场分析。若提示未确认保存，先保留需要的原话，再排查服务。

## 查看复盘并建立重练

### 阅读一条记录

1. 进入「复盘记录」，必要时点击「刷新」。列表展示最近 50 次演练，并标注已完成、已中断、已超时或异常结束。
2. 点击「查看复盘」，先检查医生与学员原话。标有「未完成转录」的文字不能视为完整发言。
3. 阅读教练分析或 AI 复盘。若有量表评价，结合具体维度、对应原话、资料版本、引用页码及原文判断反馈是否合理。
4. 对照本次训练目标，选出下一轮需要改进的一个环节。

资料不足、未观察或分析失败不等于零分。未完成专家校准的量表只能作为练习反馈，不能当作已验证的考核标准。系统的语气分析针对措辞；它不等同于声音语调、情绪或真实插话行为的准确评估。

### 添加人工点评

在记录中展开「添加点评」，选择整场点评或定位到某条原话，填写内容后点击「保存点评」。

绑定场景的记录还可调整一个评分维度，填写调整后分数和理由。医学维度调整需要提供本轮绑定资料中的页码和逐字原文。人工调整会单独留痕，原始 AI 评价继续保留。

### 建立同版本补练

1. 在绑定场景的记录中展开「建立同版本补练」。
2. 选择完整拜访或一个补练环节，填写补练说明；不填写说明时，系统默认聚焦最低分维度。
3. 点击「生成补练任务」。
4. 返回记录页，在「待重练」区域点击「开始重练」，确认配置后启动。
5. 练完后，打开原记录的「原记录与前后对比」或最新补练记录。

重练会沿用原场景和演练方式，并使用建立任务时选择的环节。系统会检查比较条件；没有同条件结果时会说明原因。环节不同的维度变化仅供参考，人工调整与原始 AI 分数分开查看。

### 查看训练变化与用量

在记录列表下方展开「查看训练变化与服务用量」。比较时留意医生、场景、资料、环节、模式及评价版本是否一致。时长和用量仅统计已记录部分；未计价或未完整计价不代表免费。

## 浏览学习资料

「学习资料」用于阅读参考内容，分为药品文档、医药代表技能、医生医院文档和政策文档。

- 药品卡片提供「概述」和「详细文档」入口。概述在当前页预览，详细文档在新标签页打开；使用前查看来源、版本和特殊资料类型标记。
- 医药代表技能提供要点导览及外部原文，作为培训参考。
- 政策文档可联合筛选发布层级和主题分类，查看匹配数量，并一键清除筛选。阅读时核对发布机关、实施时间和适用范围；医院院内制度单列。
- 医生医院分类在没有收录内容时显示空状态，可通过资料检索查找公开来源。

**学习资料与训练资料分别管理。** 浏览到一份文档，不代表它已经进入本轮评分依据；需要在「训练管理 → 训练资料」核对，并绑定到场景。药品概述、外来资料和模型生成内容不能代替专业医学审核。

## 准备可评分的训练场景

建议依次准备训练资料、医生角色、评分标准，再创建和发布场景。已有可用配置时可直接复用。

### 录入并核对训练资料

入口：「训练管理 → 内容准备 → 训练资料」。

1. 点击「添加训练资料」。填写资料名称、版本、适用范围，以及可选的来源链接、发布日期和到期时间。
2. 导入 PDF 原件，或直接填写带原文页码的正文。PDF 上限为 20 MB、200 页；导入后逐页核对正文与页码，尤其注意表格、特殊字符及缺失内容。
3. 点击「保存草稿」。
4. 在「资料核对」填写说明，点击「提交核对」。
5. 检查来源、版本、适用范围与可引用原文，填写核对说明后点击「确认核对」；需要修正时点击「返回修改」。

状态依次为草稿、待核对、已核对；返回后为待修改。已核对资料仍需检查有效期和可用状态。自我核对不代表专业医学审核，正式使用前应由专业人员确认。

更新已核对资料时，点击「创建新版本」，编辑并重新核对。需要撤下旧资料时，填写说明并点击「停用此版本」。使用旧资料的场景若提示无效，应重新核对绑定，不能忽略提示继续训练。

列表下方的「批量导入本地资料」提供 JSON 模板，单次最多导入 50 份、文件不超过 7.5 MB。下载模板填写后再上传；全部校验通过才会写入草稿，导入后仍须逐项核对。

### 创建医生角色

入口：「训练管理 → 内容准备 → 医生角色」。

**联网生成：** 在列表页填写医生姓名、医院和科室，点击「联网检索并生成草稿」。需要配置 DeepSeek 并开启公开搜索，会产生实际用量。系统复用公开资料检索和原文归档，唯一匹配身份后，将有来源的事实整理为画像草稿；未取得依据或同名无法区分时，不合并履历，也不生成可用角色。

展开「核对检索事实与原文」，检查身份、引文、来源时间及待核对项，再点击「核对并编辑画像草稿」。公开背景、来源和训练设定均可修改；互动状态、交流方式与默认训练人群属于训练设计。核对后勾选确认，点击「确认核对并保存草稿」，再点击「发布医生」，即可在训练场景中选择该角色。生成和查看结果不会自动保存、发布或覆盖已有医生。

保存时会关联本次检索；同一草稿不能重复入库，返回后可点击「查看已保存的医生角色」。角色编辑页保留本次检索原文与待核对项的入口。删除未被场景引用的角色后，检索原文及原始草稿继续保留，可重新核对保存。

检索期间可以停止；离开页面或刷新不会重新发起收费检索，返回列表时会读取最近一次医生检索，未完成的任务继续显示进度。读取失败可点击「重新读取进度」。后台停止导致的未完成任务仍按检索恢复规则处理。

**手动创建：**

1. 点击「添加医生角色」，填写姓名、专科和背景类型。
2. 填写公开背景及来源、关注人群、关注点、训练追问方式、情绪和开场白等内容。公开事实与训练设定应分别表述。
3. 保存草稿，再点击「发布医生」。场景使用前应确认医生已发布。

虚构角色适合一般练习。使用公开人物背景时，角色只代表训练模拟，不代表本人、实际诊疗意见或产品背书；不要把训练中的性格或情绪设定写成真实人物事实。

医生资料修改后覆盖当前记录，已发布医生保存后仍保持发布。历史演练保留当时快照。删除医生前先处理场景引用；仍被使用时系统会阻止删除。

### 创建评分标准

入口：「训练管理 → 内容准备 → 评分标准」。

1. 添加评分标准，填写量表名称。
2. 为每个维度填写唯一标识、名称、权重和 0 至 4 分的行为锚点。锚点应描述可以从对话中观察到的行为。
3. 对医学准确性等必须依赖资料的维度，勾选「该维度必须有有效训练资料才能评价」。
4. 确认所有维度权重合计为 100%，保存草稿，再点击「发布此版本」。

发布不代表完成专家校准。需要校准时，在已发布量表下方的「专家标注与模型校准」添加样本：选择绑定本量表的已发布场景，录入合成或充分脱敏的对话及逐维分数；只有真实、经授权专家负责的标注才能选择专家类型。

点击「调用模型运行校准」会消耗真实额度。每个维度至少需要 5 个有效专家标注，且达到页面显示的一致性条件；合成样本不能用于认定专家校准通过。运行中可点击「停止后续样本」，随后刷新进度查看已完成部分。

### 创建与发布训练场景

入口：「训练管理 → 训练内容 → 训练场景」。

**使用 AI 生成草稿：**

1. 准备至少一名已发布医生、一份已发布量表及一份有效的已核对资料。
2. 展开「AI 生成拜访场景」，填写产品、治疗领域和本次训练目标。
3. 选择医生、量表、拜访情境、难度、时限和本次生成依据。可选用已确认的经验案例。
4. 点击「生成场景草稿」，等待完成。生成会调用模型并产生用量。
5. 核对背景、医生开场白、核心异议、完成标准，以及「生成依据」中的资料版本和引文；必要时修改并保存。
6. 点击「预览已保存配置」，确认无误后点击「发布此版本」。

**手动创建：** 点击「手动创建场景」，填写场景名称、目标、情境、医生、量表、建议时长、训练环节和绑定资料，保存、预览并发布。没有有效资料时，不应把医学准确性反馈视为已核实结论。

只有已发布场景会进入开始页的场景列表。发布遇到错误时，按提示核对医生、量表和资料状态。修改已发布场景或量表时使用「创建新版本」，重新核对后发布。

### 导出或导入场景模板

在场景列表下方展开「分享或导入训练场景」。先选择场景，再点击「导出当前场景模板」；接收方通过该区域上传 JSON 文件，文件上限为 7.5 MB。

模板包含场景、医生、量表和资料文本，不能代替完整系统备份。导入后各项进入草稿，外部审核和专家校准状态不会继承。分别核对并发布医生、量表、资料和场景后，才能用于演练。

## 检索公开资料与开启追踪

入口：「训练管理 → 内容准备 → 资料检索」。需要配置 DeepSeek，并启用公开搜索。

| 助手 | 输入主题时应说明 |
| --- | --- |
| 政策 | 主题、地区、发布机关或需要检查的政策范围 |
| 医生公开资料 | 姓名、医院、科室，尽量消除同名歧义 |
| 同类药品 | 目标药品、机制、获批地区及希望比较的范围 |

1. 选择助手，输入主题，点击「开始检索并归档」。
2. 等待任务完成；同一工作区同时只运行一个检索任务。
3. 阅读整理结果、真实引文和待核对项，打开 HTML 阅读副本或下载原件，检查版本和上下文。
4. 需要持续关注时，显式开启每日追踪；不需要时暂停。追踪默认关闭，每 24 小时执行一次，仅在本机后端运行时生效，并产生模型和搜索用量。
5. 将核对后的内容另行录入训练资料，完成资料核对并绑定场景。

检索结果不会自动覆盖已核对训练资料、医生角色或学习资料卡片。医生角色页的联网生成入口可将医生检索结果整理为待人工核对的画像草稿；通用资料检索结果仍按上述步骤录入。访问失败会保留旧版，部分完成不表示所有来源均已核实。文件变化也不自动证明政策效力、医生现任职位或药品获批范围改变；须回到权威原文核对。

详细的来源归档、版本和任务恢复说明见[检索助手说明](research-agents.md)。

## 提炼与复用经验案例

1. 在演练记录中找到案例提炼区域，选择一条学员原话。
2. 补充案例名称、适用情境、回应方式、处理理由及适用边界，保存为待核对案例。
3. 进入「训练管理 → 训练内容 → 经验案例」检查和编辑。
4. 保存修改后，点击「确认适用边界」。已确认案例可以通过「用此案例生成场景」作为新场景参考。

案例支持 JSON 和 Markdown 导出；分享的 JSON 案例可导入，文件应小于 100 KB。外来素材的原话和来源须重新核实，修改已确认案例后也须重新确认。

案例只是沟通参考，不是独立医学证据，也不能证明某种表达在真实拜访中有效。

## 服务检测与费用查看

### 手动检测服务

进入「服务设置」，点击「刷新」检查语音和分析服务。打开页面本身不会自动检测；下方保留上次检测结果，不能把历史正常状态当作当前连接保证。刷新会实际调用外部服务并产生用量。

密钥在后端配置文件中填写，页面用于查看状态。修改配置后重启后端，再按需检测。没有配置密钥时仍能启动页面，但无法完成对应的语音或模型功能。

### 维护计价依据

进入「训练管理 → 使用成本 → 用量计价」，按供应商价格或实际合同填写服务、模型、计量单位、数量、金额、币种、来源和核对日期，再点击「保存计价依据」。

每次演练保存启动时的价格快照，修改只影响后续演练。人民币和美元分别累计；缺失价格或用量会显示未计价。估算不等于实际账单，最终费用以供应商记录为准。

演练、生成场景、资料检索、每日追踪、模型校准和手动服务检测都可能产生实际用量。查看已有记录、已归档 HTML 不会重新执行模型检索。

## 常见问题

| 现象 | 处理方法 |
| --- | --- |
| App 无法连接服务器 | 检查网络和服务器状态；由管理员确认 HTTPS、账号登录配置及 `/api/ready` 正常 |
| 点击开始后提示配置缺失 | 按提示填写对应后端密钥，重启后端；练习和实战使用不同的额外语音配置 |
| App 不允许使用麦克风 | 在 Android 应用权限中允许麦克风，确认系统麦克风开关已开启，再重新开始 |
| 麦克风已连接但没有转录 | 确认未静音、系统选中了正确输入设备，检查 SeedASR 状态和网络 |
| 医生有文字但没有声音 | 检查系统音量、输出设备和页面朗读错误提示；按提示重试朗读。持续异常时确认保存后重新开始 |
| 医生或教练生成失败 | 保留当前原话，按页面提示重试，并检查分析服务；重试可能产生额外用量 |
| 没有可选场景或开始按钮不可用 | 等待资料核对完成；遇到错误点击「重新读取场景」。场景须已发布，相关配置须有效 |
| 资料或已发布配置无法直接编辑 | 对训练资料、场景和量表使用「创建新版本」；医生资料直接保存修改 |
| 量表保存按钮不可用 | 检查维度权重是否合计 100%，必填字段和分数锚点是否完整 |
| 复盘没有分数或显示未观察 | 检查是否自由练习、是否有有效资料、对应行为是否发生，以及分析是否完整 |
| 结束后长时间没有保存确认 | 保留页面和需要的原话，不要反复开始新演练；检查后端、数据库及页面错误，再按运维说明处理 |
| 新记录没有出现在列表 | 点击记录页「刷新」，确认本次是否已收到保存确认；列表仅展示最近 50 次 |
| 资料检索只部分完成 | 查看失败来源和待核对项，检查原件与正文；不要将部分完成等同于审核通过 |
| 每日追踪没有执行 | 确认已开启追踪且本机后端持续运行，查看最近任务和错误提示 |
| 历史记录可看但无法重练 | 检查旧场景、资料是否有效，以及是否属于旧工作区；系统不会自动合并其他工作区资料 |

出现数据库保存失败但已留存本机恢复副本等提示时，按[部署运维](operations.md)处理。不要通过删除记录目录、数据库卷或重建旧容器来尝试修复。

## 首次安装与启动

### 本地开发方式

用户端的 Android 环境、安装与调试见 [Android 打包](android.md)；下面的 Vite 服务仅用于 Web 管理端。

需要 Node.js 22+ 和 uv。以下命令均在项目根目录执行。

先安装前端依赖；仅在尚无 `backend/.env` 时复制配置模板，已有配置不要覆盖：

```sh
npm --prefix frontend ci
cp -n backend/.env.example backend/.env
```

编辑 `backend/.env`，按需要填写：

| 功能 | 必需配置 |
| --- | --- |
| 两种语音模式与分析 | `SEEDASR_API_KEY`、`DEEPSEEK_API_KEY` |
| 辅助练习的医生朗读 | `DOUBAO_TTS_API_KEY` |
| 实战语音对话 | `DOUBAO_API_KEY` |
| 公开资料检索 | `DEEPSEEK_API_KEY`，以及 `DEEPSEEK_SEARCH_ENABLED=true` |

密钥只填在后端，不要添加 `VITE_` 前缀，也不要提交或分享 `.env` 文件。默认模型、音色与资源要求见配置模板和 [README](../README.md)。

在两个终端分别启动后端和前端：

```sh
# 终端一
npm run dev:api
```

```sh
# 终端二
npm run dev -- --host 127.0.0.1
```

打开 [http://127.0.0.1:5173](http://127.0.0.1:5173)。修改后端密钥后需要重启后端。停止使用时，先结束演练并确认保存，再在两个终端分别按 `Ctrl+C`。

### Docker 方式

首次部署时准备根目录 `.env` 和 `backend/.env`，将根目录配置中的 `POSTGRES_PASSWORD` 换成长随机密码，后端密钥按上表填写。已有配置不要覆盖。

```sh
cp -n .env.example .env
cp -n backend/.env.example backend/.env
# 编辑上述配置并保存后执行
docker compose up -d --build --wait
```

打开 [http://127.0.0.1:8080](http://127.0.0.1:8080)。正常停止使用 `docker compose down`；该命令保留数据卷。不要对需要保留的数据执行 `docker compose down -v`。

已有部署升级前，先按[部署运维](operations.md)备份数据库和原文文件。旧容器中尚未持久化的原文必须在重建前导出。

## 数据保存与使用边界

系统保存文字转录、教练分析、评价、人工点评和可用用量等记录，不保存原始音频；语音会发送到所配置的外部语音服务，相关对话内容和资料会按功能发送给模型服务。只使用允许向这些服务提供的训练内容。

本地开发未配置 `DATABASE_URL` 时，演练记录通常保存在 `backend/data/sessions`；Docker 使用 PostgreSQL 保存记录，资料原件和检索归档仍有独立文件存储。备份应同时覆盖数据库和文件，仅导出场景模板不能恢复全部记录。

训练资料、医生角色、场景和量表共享；个人演练记录、点评、重练、经验案例和统计按账号隔离。本机免登录模式不得对外开放；公网须启用登录和 HTTPS，见[服务器与 CI/CD](server-deployment.md)。正式医学内容使用前须核对原始来源、版本和适用范围；系统不提供真实诊疗建议、产品背书或考核认证。

部署、备份与恢复见[部署运维](operations.md)；更详细的运行配置见[架构与部署](architecture.md)。
