# 项目新增性能优化 20 轮 · 2026-11-07 batch4

从干净的 `main` / `b88a26efa4f1251a12c8217276ff7cd0398a5a75` 建立新基线，完成 **20 个新的独立候选，最终保留 10 项、回退 10 项**。前两批延迟改动已在基线内，没有重复计算旧轮数或旧收益。新增依赖为零；未提交、推送或部署。

## 最终收益和适用范围

- **学习统计 API：23.277 → 18.736ms，减少 19.5%。** 本机 Fastify 注入真实 `/api/training/outcomes`，包含 20 个租户、600 份已保存会话及各 600 条任务/事件；当前租户有 30 份会话。会话读取、SQLite、统计和响应序列化实际执行。数据库按租户限制任务与事件读取；单租户小数据为 0.2560 → 0.2561ms，基本不变。
- **网页归档解析：4.888 → 3.012ms，减少 38.4%。** 1200 个链接元素的合成 HTML，保留原文本、首个链接标题、规范化去重、PDF/附件优先级和来源安全限制；不包含网络下载耗时。
- **合规规则读取/校验：32.413 → 1.578ms，减少 95.1%。** 真实 SQLite、20 条规则共用一份长政策原件，固定模型响应；每次规则快照只读同一政策一次，模型结束后仍重新加载快照并核对版本。不是供应商推理速度提升。
- **明确超出 24 句上限的输入：4.934 → 0.060ms。** 真实临时语料文件和 SQLite，输入总长小于 API 的 6000 字上限；仍返回同样的 unavailable、空结论和“本段过长”提示，只跳过必定不能使用的资料检索。没有提高医学判断覆盖率或缩减校验。
- **前端重复引文核对：0.08164 → 0.01865ms，减少 77.2%。** Node 中执行前端函数，400 条历史、8 条候选引文；仅本次调用复用原话规范化，保留角色、完整状态、重复编号和引用检查。这是微基准，不是浏览器帧率证明。

## 方法与独立对照

每轮从当时此前保留的版本建立 A/B 源码快照，目标负载按 `ABBAAB` 启动六个独立 Node 进程，小负载按 `ABBA` 启动四个；每进程三次准备调用后测七批，每批按估算重复约 30ms，最多 1500 次。全部本任务性能测量串行执行，没有与本任务测试/构建并行。机器非独占、未绑核，计时为本机输入的样本中位数，不是线上 p95/p99。

保留门槛：目标负载中位数减少至少 5%、三组配对至少两组达到 5%、大小负载输出 SHA-256 分别一致；小负载退化不超过 15%，或绝对差小于 0.05ms。记录每批 CPU 用时和额外验证结果，不能只用一次最快值决定。

追加八组 `ABBAAB` 对照，每进程九批。第 1 项加入真实 API；第 10 项使用真实文件和 SQLite，以及 API 接受但超分句上限的输入；第 12、14 项检查价格配置边界。最终对十项保留代码再执行 28 组 `ABBA` 综合对照，输出全部一致。

**第 12 项最终回退：** 初测使用 4800 条价格的压力输入，索引显示约 61% 收益；检查到配置 API 最多支持 50 条价格后，用 48 条合法配置复测仅有 4.64% 改善、配对未达门槛，因此移除价格索引。原始超大压力数据仅保留为负结果，不能当作生产计费成果。

第 2 项增大文件读取批量虽然目标负载约快 8%，小负载未过门槛，回退；第 13 项字段映射移出函数只有一组配对超过门槛，回退。其余收益不足的分块前缀、文件正则、规则/原话索引等均恢复。重测和边界复核不计为额外候选。

## 正确性与验收

- 新增 SQLite/PostgreSQL 范围查询回归：默认跨租户接口保留，指定租户只返回该租户，空租户参数也不会退化成全库读取，完整原文不丢失。学习管理的既有角色检查、所属人筛选和审计继续执行。
- 网页回归覆盖相同 href、不同 fragment 规范化为同一 URL、首标题、PDF/附件稳定优先级、跨页面不复用缓存，以及脚本、内网、凭据和非标准端口拒绝。空白规范化增加 Unicode/ASCII 边界和 200 组合成对照。
- 计费回归核对 Decimal 精度、首个重复价格、不回退到后续“正常”价格掩盖损坏快照、缺失提示的首次顺序、空用量及负数/NaN 拒绝计价。
- 医学回归确保超长或超过 24 句时保留当前语料版本、明确未核实且不调用检索；6000 字合法长度仍进入检索。合规回归确保每条规则仍核对版本，同一政策只在当前快照中复用，模型结束后撤回政策会清空发现并返回 unavailable。
- 前端回归确认规范化缓存只在当前调用内有效，不接受医生或非完整学员消息；重复编号及修改原话后会重新校验。
- **后端 89/89、前端 185/185、训练浏览器 10/10、管理端 E2E 22 通过/6 跳过，零失败。** 后端包含独立 PostgreSQL 17 容器，结束后已删除。单独定向阶段未配置 PostgreSQL 而跳过的一项，随后完整后端阶段已实际执行通过。
- 后端/Web/Android 前端构建通过；lint 零错误、2 条既有 Fast Refresh 入口警告；`git diff --check` 通过。未改变依赖或生产配置。
- 十项保留变换从基线归档逐文件重建最终前后端源码哈希，旧优化完整保留。源码归档排除 assets、依赖、环境文件和业务数据。
