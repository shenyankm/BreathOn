# 性能优化 · 2026-11-05

比较基线：`60ab40282c9b14ad711c5b59196a79b4c5d1d4f8` 中的
`backend/medvisit/services/practice.py` 和 `backend/medvisit/knowledge/corpus.py`。
这两个文件在本轮开始时没有未提交改动。保留工作区中既有的其他改动；不新增依赖、数据库迁移或对外接口。

## 实施范围

- ASR 快照更新复用本次请求已经建立的消息索引。修正已有消息时保持对象和附加字段，新增消息按原顺序追加；继续执行检查点保存、转录事件、政策和医学检查，以及旧建议失效处理。300 条已有消息、100 条新增消息的测试中，历史遍历由 **80,100 次降至 300 次**。
- 审核匹配在单次调用内将每个来源页归一化一次，再与同源审核凭证比较。20 份同源资料、单页场景的归一化由 **40 次降至 21 次**。保留凭证优先级、重复页码的原顺序、每次读取有效状态和全文哈希；不跨请求缓存审核状态。
- 医学检索按需生成派生资料分块，不预先保存全部分块。分块范围、评分、排序、每来源上限和返回字段不变；命中的候选仍由原有排序保留，不声称所有检索场景都具有固定内存上限。

## 本机合成基准

先断言新旧输出等价，再交替测量五组重复的中位数。数据为合成文本，不访问模型、麦克风或真实用户数据。耗时只代表本地处理，不代表线上端到端延迟。

| 场景 | 基线 ms/次 | 优化后 ms/次 | 收益 |
| --- | ---: | ---: | --- |
| ASR：1,800 句修正、200 句新增 | 28.7860 | 5.5169 | 5.22 倍 |
| 审核匹配：20 份同源凭证、100 页 | 74.8941 | 45.2558 | 1.65 倍 |
| 检索：140 万字无关派生资料 | 18.6116 | 18.2742 | 耗时接近波动范围；主要降低分配 |

检索选择阶段的 tracemalloc 临时内存峰值为 **4,383,989 → 27,108 B（减少 99.4%）**。
该测量隔离了必须保留的审核读取和全文哈希，不包含已存在的原文或进程总内存。

基准同时检查正向命中、同分顺序、不同 limit 和过期哈希凭证的输出等价。
回归测试覆盖新增/修正消息、重复快照、消息对象与元数据保留、多凭证选择、资料修订和撤销、重复页码与凭证标识、未命中分块的内存上限。
