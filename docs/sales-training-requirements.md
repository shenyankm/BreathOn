# 医药代表智能演练助手题目解析与需求优先级

> 需求／方案基线：保留需求来源与当时设计，不代表全部已实现。客户端拆分、课程与管理功能已有后续调整；当前实现见[功能范围](platform-completion.md)和[架构](architecture.md)。文中的旧 `/app` 方案不再是部署入口。

原题：

> 1. 销售培训 · 医药代表智能演练助手：聚焦医药代表一线拜访能力的实战培训。针对传统培训成本高、与真实市场严重脱节的痛点，AI自动合成含真实医生情境的拜访演练素材，并构建带智能反馈的复盘机制，让新人低成本反复训练，把个体经验沉淀为整个团队的群体竞争力。

这道题的核心是：**把真实拜访中的难题转成可反复练习的场景，用有依据的反馈帮助新人改进，再把有效经验变成可复用的培训素材。**

完整闭环是：

**资料与一线经验 → AI生成场景 → 模拟拜访 → 复盘反馈 → 针对性重练 → 优秀案例沉淀。**

下面的 P0 是题目核心及其必要支撑；P1、P2 是逐步增强的能力，不代表题目明确要求了所有功能。

本轮实现范围按用户最新指示为 **P0 + P1，P2 不实现**。实现与验收结果单独记录在 [训练交付记录](training-delivery.md)。

| 优先级 | 需求 | 对应题意 | 最小验收标准 |
|---|---|---|---|
| **P0-1** | **可信的训练资料** | 演练需要贴近真实市场 | 产品资料、典型拜访问题有来源；区分已确认事实与模拟设定，不能靠模型编造医学依据 |
| **P0-2** | **AI自动生成拜访场景** | “自动合成含真实医生情境的拜访演练素材” | 输入产品、医生背景和训练目标，生成拜访背景、医生关注点、核心异议、任务目标及评价要点，而非只生成一段介绍 |
| **P0-3** | **能互动的模拟医生** | “一线拜访能力的实战培训” | 医生根据学员回答追问、质疑或调整态度；有时间限制和关注重点，不能始终配合学员完成话术 |
| **P0-4** | **有证据的智能复盘** | “带智能反馈的复盘机制” | 指出具体原话、问题原因、改进方式和参考表达；覆盖需求挖掘、证据沟通、异议处理、拜访收尾等能力 |
| **P0-5** | **针对弱项反复训练** | “让新人低成本反复训练” | 复盘后能直接重练相关场景，保留前后记录；使用一致标准比较表现，不能只给一次总分 |
| **P0-6** | **经验变成可复用素材** | “个体经验沉淀为整个团队的群体竞争力” | 将有效提问、异议处理和优秀片段整理成案例，经过确认后保存、复用或导出，供其他人训练 |
| **P1** | 场景多样性与难度梯度 | 增强真实感和训练覆盖面 | 支持首访、复访、时间紧张、证据质疑等情境；难度变化体现在医生行为中 |
| **P1** | 培训师校准与轻量团队使用 | 提高反馈可信度和经验传播效率 | 培训师能修订评价、审核案例；能把指定场景交给其他学员练习 |
| **P1** | 个人进步与成本记录 | 验证培训价值 | 查看同类任务的能力变化、练习次数、素材准备耗时及单次训练成本 |
| **P2** | 企业管理与展示增强 | 规模化运营 | 批量任务、部门权限、团队看板、认证、CRM对接、数字人形象等 |

有三个容易理解偏的地方：

- **“真实医生情境”重点是真实工作约束。** 科室、诊疗关注点、证据偏好、常见异议和拜访时间，比使用真实医生姓名更重要。模拟角色需要明确标识。
- **“自动合成素材”必须是独立可见的能力。** 只有人工配置好的医生和聊天入口，还不足以体现题目要求；应能展示从资料到新场景的生成过程。
- **“经验沉淀”不能等同于保存聊天记录。** 需要提炼成“什么情境下，什么做法有效，依据是什么”的可训练案例。

首版建议只聚焦 **一个产品领域、三类典型拜访情境、一套评价标准**。演示时串起一条完整路径：

**导入资料 → 生成场景 → 新人演练 → 引用原话复盘 → 针对弱项重练 → 保存为可复用案例。**

这也与项目文档中的“选择医生与场景 → 演练 → 按原话和资料复盘 → 针对性重练”主线一致。题目额外需要突出的是**自动生成素材**和**经验复用**，可以先用案例保存、导出承接，无须立即恢复完整企业培训平台。[项目主线](platform-completion.md)

以上为需求拆解，优先级不代表现有实现已通过验收；“降低培训成本、提升真实拜访能力”仍需试用数据验证，不能由演示效果直接推出。
