# 管理后台真实功能接入

管理后台沿用 Web 原型，所有保存、发布、审核和服务设置通过当前工作区接口持久化。无新增外部依赖，复用 SQLite / PostgreSQL 平台存储与审计。前后端需一起更新。

| 管理功能 | 接口与实际效果 |
| --- | --- |
| 系统设置 | `/api/admin/settings` 保存版本化设置；医生推荐作用于 App 推荐入口，评分关闭后跳过实时评分和最终评分模型调用 |
| 发布审核 | `/api/admin/catalog/{kind}/{id}/approval` 为药品、医生、资料、场景、课程记录审核意见；发布接口在事务内执行审核门槛 |
| 审核职责 | 支持管理员直接发布、不同管理员双人审核、不同医学与合规审核人；审核人必须是已配置管理员，内容或设置版本变化后重新审核 |
| 内容版本 | `/api/admin/versions` 与 `/api/admin/catalog/{kind}/{id}/history` 返回实际目录版本及历史 |
| L1–L4 课程 | `/api/catalog/lesson` 支持创建、修订、审核和发布；`/api/curriculum` 只展示已发布课程，修订保留课程 ID 与个人完成记录 |
| 产品训练 | 从产品进入关联训练场景，按真实药品 ID 创建场景；未发布药品不能用于生成 |
| 医生详情 | 科室、区域、沟通风格筛选；展示配置策略及关联的实际训练记录 |
| 用户画像指标 | `/api/admin/audience-metrics` 汇总工作区真实训练人数、有效评分和维度均值；不将工作区总数伪装成画像子群指标 |
| 代表记录 | 管理员查看真实记录、医生关联及有效评分，保留原有权限和详情入口 |
| 健康观察 | `/api/health/observations` 保存个人手动观察；逐条明确授权后进入管理员审核；通过后由 `/api/health/shared` 提供给工作区代表 |

健康观察默认私有，工作区共享默认关闭。本人不能审核本人提交的记录；代表共享视图不包含账号身份。撤回在服务端立即停止返回该记录，即使审核并发修改了版本也允许本人撤回；已打开页面每 5 秒刷新，并在重新聚焦时刷新，页面隐藏或请求失败时清除共享显示。已被阅读或截取的信息无法追回。所有响应禁止缓存。

现有单管理员安装默认保留管理员直接发布；切换双人或医学/合规规则需有对应管理员账号。没有将原型示例账户或数字当作真实业务数据。课程首次入库时，待审核课程以及包含未核验数字的课程保存为草稿；管理员核实后才可发布。已有持久化课程不被启动过程覆盖。

没有接设备或项链接口；健康观察是用户明确选择的手动提交闭环，保留测量条件和局限，不推断疗效、诊断或医学能力认证。该功能不需要设备接入；以下验收未调用付费模型或语音服务。

## 配置与发布操作

1. 由运维在服务器配置管理员账号，按[账号登录](server-deployment.md#账号登录)重启生效；系统设置不能创建账号或授予管理员身份。
2. 在 Web「系统设置」调整推荐、评分、健康共享和各内容审核规则，点击「保存设置」。医学与合规审核人只能从已配置管理员中选择。设置冲突时先「重新读取」，核对后再保存，不重复提交旧版本。
3. 在对应药品、医生、训练资料、场景或课程编辑页保存草稿，核对来源及适用范围。课程位于「训练内容」，课程发布前不会出现在 App 已发布课程列表。
4. 在「发布前审核」填写意见并确认当前版本；双人审核需两位不同管理员，医学与合规模式需各自被配置的两位不同管理员。退回后先修改内容，再重新审核。
5. 满足门槛后使用该内容的发布按钮。内容或审核设置版本变化会使旧票失效，不能用旧审核发布新内容。管理员直接审核模式沿用原内容发布规则，不把多人投票作为默认强制步骤。
6. 在「系统设置 → 内容版本」检查实际版本与状态，再在 App 验证代表可见范围。已发布旧版本不会因修改后续审核规则自动撤回。

代表端「系统设置」中的个人偏好与此处工作区规则不同。关闭工作区推荐后仍可手选医生；关闭评分不删除历史成绩；提醒偏好不代表已实现系统推送通知。

## 健康观察从个人保存到共享

1. 管理员按业务需要在 Web「系统设置」开启「数据上传到代表端」并保存；默认关闭。
2. 本人在 App「我的 → 系统设置 → 健康观察与授权」填写指标、数值、单位、时间、观察条件和局限，点击「保存为个人记录」。此时只有本人可见，不因保存自动授权。
3. 对指定记录勾选授权说明，点击「授权并提交审核」。共享未开启时仍可保存个人记录和撤回已有授权，但不能提交共享。
4. 另一位管理员在 Web「系统设置 → 健康观察数据审核」填写审核意见，选择通过或退回。本人不能审核自己提交的记录。
5. 通过后，工作区代表在「代表端共享观察」看到不含账号身份的指标与条件。文本仍不得填写姓名、联系方式等身份信息。
6. 本人可随时点击「撤回授权」。服务端立即停止返回；已打开页面每 5 秒及重新聚焦时更新，隐藏或读取失败会清除共享显示。撤回不能追回已被阅读或截图的信息。

健康观察审核独立于药品等内容的多人发布规则。关闭共享会停止提供共享数据，不删除个人记录；再次开启前应检查已有授权与审核状态。

## 常见排查

| 现象 | 核对项 |
| --- | --- |
| 保存冲突 / 409 | 数据或设置已更新，重新读取当前版本后再操作 |
| 审核后仍无法发布 | 内容和设置版本、不同审核人及职责是否满足；资料自身的发布条件是否有效 |
| 共享为空 | 工作区开关、逐条授权、审核状态、撤回状态及读取错误；不要用展示数字替代真实数据 |
| 课程未出现 | 是否发布、当前账号/工作区、客户端刷新；初始化不会覆盖已有持久化课程 |
| 评分为空 | 工作区评分开关、是否自由练习、有效量表/证据与分析完成状态 |

审核记录、个人健康观察及真实拜访内容均不应粘贴到公开问题或 CI 日志。
