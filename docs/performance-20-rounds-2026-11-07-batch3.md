# 清理后新增 20 轮性能优化 · 2026-11-07（第 3 批）

以当前工作区建立全新基线，完成 **20 个独立候选，保留 12 个、回退 8 个**。此前两批实验没有计入本批。Git 基点为 `898c481dc2e7b88234f23112c7c8607e29cfcde9`，本批基线还包含已有学习闭环改动及本会话上一轮清理；不能用 Git HEAD 单独代替基线。没有提交或部署。

关键结果：真实 SQLite 和记录文件参与的本机 Fastify HTTP 注入请求从 **36.480ms → 29.658ms，耗时减少 18.7%**；同样输入的内存统计计算减少 62.4%，难题和场景关联减少 97.9%。这些百分比只对应下面的本地合成负载，不是线上响应或模型语音延迟。

## 测量方法

- 环境：v22.23.2、macOS-27.0.1-arm64-arm-64bit。没有新增运行依赖；不读取 `.env`，不使用业务数据，不调用付费供应商。
- 每轮冻结前版 A 与候选 B，目标负载按 `ABBAAB` 运行 6 个隔离 Node 进程，小负载按 `ABBA` 运行 4 个。每个进程先执行 3 次预热/估算，再测 7 批；根据估计自动选择重复次数，上限 1,500。每批前显式 GC，保留批次均值、CPU 和输出哈希。
- 保留条件：目标负载的进程中位数之中位数至少降低 5%，3 组配对至少 2 组降低 5%；大小负载分别输出哈希一致。小负载退化不能超过 10%，除非绝对差小于 0.001ms。第 2 轮即因小负载退化回退，负结果保留在原始 JSON。
- 所有性能测量串行进行，没有同时运行本任务的构建和测试。机器并非独占，没有绑核。计时不包含 fixture 创建、输出哈希和结果断言后的清理。
- `p95_ms` 是批次均值的 p95，不是单个 HTTP 请求的 p95。不同轮次百分比不能相加。
- 学习统计的逐轮基准使用真实路由计算和合成存储接口，便于隔离计算开销；综合复测另加入真实 Fastify 路由、SQLite 表和记录文件的 `learning_http`。HTTP 注入不经过外部网络，文件处于预热缓存状态。

## 起始到最终版本综合复测

每个场景使用 `ABBA` 四个隔离进程，每进程 7 批，全部输出哈希一致。压力样本用于观察规模增长，不能直接代表常见单次练习；小负载对照见每轮 JSON。

| 本机 HTTP 注入 + 真实 SQLite / 240 记录文件 | 36.479625 | 29.658042 | 18.7% |
| 360 难题 / 1,200 场景关联 | 3.006469 | 0.062189 | 97.9% |
| 10 维度 / 160 次人工复核覆盖 | 0.033420 | 0.014887 | 55.5% |
| 长原话的重复评分卡引用核对 | 0.190584 | 0.027993 | 85.3% |
