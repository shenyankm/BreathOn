# 用户学习闭环修复与验收 · 2026-11-07

基于 `898c481dc2e7b88234f23112c7c8607e29cfcde9` 修复上一轮产品分析中的六类问题。沿用现有 Android 三个导航入口、Web 管理后台、SQLite/PostgreSQL、审核和场景生成机制；没有新增依赖，没有删除历史记录或自动将旧任务认定为已掌握。

## 从反馈到下一次行动

复盘先展示一个训练重点、可核对原话、改进动作和直接练习入口。最新完整复盘保留，逐轮提示与医学核验移入可展开内容。高级补练表单默认收起，保留手动选择环节和填写说明的能力。

首页优先承接待练、待新情境验证和待培训师复核任务；没有待办时，根据最近一次有效训练安排下一步。旧训练条件失效时推荐重新建立有效基线，不把用户送回无法启动的旧任务。

## 学习状态与证据

| 当前状态 | 推进条件 | 后续状态 |
| --- | --- | --- |
| 待练 | 目标维度达到 3/4 或以上，原话可核对，记录有效，且人工修订没有否决该目标表现 | 待新情境验证 |
| 待新情境验证 | 同量表、同环节，另一医生/背景/异议/难度的有效情境，实战且无实时辅助，目标行为有依据 | 待培训师复核 |
| 待培训师复核 | 独立培训师选择完整学员发言、填写逐字引用及观察理由，并重新核对训练版本 | 本次迁移表现已复核 |
| 待培训师复核 | 培训师要求继续验证 | 待新情境验证 |

- 低分、缺少原话、伪造引用、未完成分析或无有效目标的记录，不会自动成为掌握证据。
- 已有基线本身满足目标行为条件时，可直接安排新情境验证。
- 更换标题或复制场景 ID 不算不同情境。验证分数不混入原场景的同条件分数差。
- 培训师不能复核自己的记录，学员不能调用管理复核接口；所有读取及确认保留审计。
- 人工修订影响后续目标和状态判定，原始 AI 评价保留，不静默改写历史分数。
- 培训师复核一次迁移表现，不会自动完成量表专家校准，也不等于医学审核、职业认证或已证明培训有效。

## 版本失效与恢复

旧任务遇到医生、资料或场景变化时，保留严格版本检查，并提供归档及按当前版本重新练习的出口。重建基线不携带旧任务 ID，避免把新旧版本混算；旧记录、原对比和任务历史保留。缺少有效目标的旧任务同样提示重建基线。

新状态保持幂等恢复：重复结算不会推进两次，过时记录不能覆盖较新的结果，已经归档或复核的任务不会因恢复重开。新 Android 前端与后端应一起更新，旧 APK 不具备新状态与恢复操作的完整界面。

## 拜访难题回流

代表在练习首页提交一个脱敏沟通难题，经明确确认后进入现有拜访审核队列。培训师采纳为模拟情境后，复用既有案例生成场景及发布规则。代表在自己的进展中看到审核反馈与已发布场景入口，草稿不开放练习。

新增提交标识让请求结果不明时可以安全重试：同标识同内容返回同一草稿，不同内容不能覆盖已有提交。表单失败保留输入，已保存草稿可继续编辑；不自动发布、不把代表观察转成医学事实或医生私有偏好。

## 可核对的闭环统计

统计依据为当前账号或管理工作区实际保存的记录、任务与复盘访问事件，显示分子和分母，不制造无样本百分比。个人近 7/30/90 天的分数变化与累计闭环统计分开展示。

- 首条已保存记录有效的用户 / 有保存记录的用户；不能称为全部新用户的首次激活率。
- 已记录复盘访问后建立重练的记录 / 已记录复盘访问的记录；历史阅读不补算。
- 原目标仍需巩固或核实的有效重练，以及有效无提示验证中观察到目标行为的次数。证据不足不能直接解释为能力失败。
- 仍需练习、待验证、待复核及本次迁移表现已复核的任务数量。
- 次周回练：按 UTC 自首条记录第 7–13 天统计，仅纳入已满 14 天的用户。没有完整观察样本时明确显示样本不足。

这些统计用于发现操作流失与安排训练，不支持因果性培训效果结论。

## 仍需真实人员验证的事项

未执行真实供应商语音、APK/物理设备、弱网及真实用户留存试验。场景生成的回流 UI 回归使用明确标注的合成场景，未调用收费模型，不据此证明生成质量。

评分有效性继续依赖经授权专家的独立标注与校准。下一步应让目标用户独立完成基线、阅读反馈、重练、换情境验证及延后复测；由训练目标对应的专家核对原话与表现，记录分歧、同类问题复现和样本流失。观察窗口未满、数据缺失或专家意见不一致时保留待核实状态，不能用本次自动化通过率代替学习效果。
