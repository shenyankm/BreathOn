# 场景技能接入与真实模型验证

> 历史验收／设计记录：只描述文中日期与版本，不作为当前入口、功能清单或生产状态。现行指南见[文档索引](README.md)。其中忽略目录下的日志、截图和报告属于本机证据，干净克隆不一定包含。

日期：2026-10-27。模型：实际配置的 `deepseek-flash`，上下文 `1_000_000` tokens，temperature=0，输出上限2000 tokens。输入全部是合成培训文本，没有调用麦克风、ASR、TTS或创建正式演练记录。

## 运行行为

- `medical-rep-academic-visit`作为基础指导加载；研究数据、HR/NNT等线索补充`medical-rep-evidence-communication`；购物卡、统方、隐私、疑似不良反应等线索补充`medical-rep-promotion-compliance`。
- 练习按可见记录中的最后一条医生和最后一条学员消息选择技能；复盘扫描全部可见记录。分流基于关键词，可同时加载多个技能，没有额外分类模型调用。
- `LocalSkillLoader`加载的是完整技能正文；来源说明与教学练习不自动注入，不将网页例子当临床证据。
- 练习使用两个并发Agent请求，分别生成医生回应和教练指导，只共享原始结构化记录；复盘只有教练请求。对外返回的JSON字段不变，使用量累计两次实际调用。

## 实测发现并修正的问题

| 问题 | 修正 |
| --- | --- |
| 操作事件被当成额外学员消息；医生与学员角色误归属 | 改为单份JSON记录，显式`speaker`，事件放在`interaction_events`中 |
| 把生成的正确参考话术当作学员已经说出的内容，甚至医生夸错误答案已更正 | 医生和教练拆成独立并发推理，互不读取生成结果；教练先评原文再写示例 |
| 编造总轮数、按钮次数或完整结束状态 | 不推断总轮数；按钮次数及结束状态由实际事件直接生成，未知和中断明确区分 |
| 缺少音频时遗漏限制说明 | 文字语气字段保留“声音语调未评估”，不从采集音量推断情绪 |
| HR术语被模糊改写，或NNT/百分点混淆 | 循证技能明确HR为瞬时危险之比，并用另一组数值与不同随访时点复测 |
| 英文缩写紧贴中文时漏分流 | 改为英文字符边界，覆盖“HR与NNT”“SOP未知”等，并补充统方/好处费回归用例 |

迭代中出现过一次`BridgeError`，该轮未留到更底层原因，不能归因为已确认的供应商或解析缺陷。保留原失败记录；最终轮与重点复测均未再出现该错误，仍保留错误返回与取消关闭机制。

## 最终一轮：10个场景

完整输入、技能选择、原始教练JSON与最终结果（本机证据：`backend/data/validation/coaching-live-20261027-155301.json`）。该轮为17次真实上游调用，表中结论来自逐项阅读输出，不是仅靠关键词命中或JSON解析成功打分。

| 场景 | 核心验收结果 |
| --- | --- |
| 30秒、安全性优先 | 正确引用30秒，指出机制先行与医生关切错位，缺资料时提示核实 |
| 对照12%、干预9%、固定一年 | 绝对下降3个百分点、相对下降25%、NNT向上取整34；不保证个体受益 |
| HR=0.75、缺固定时点风险、跨研究比较 | 说明瞬时危险之比；拒绝推出ARR/NNT及跨研究优效 |
| 每50盒换购物卡 | 停止数量与财物交换，不把改名当合规化 |
| 疑似不良反应、因果未明与病历信息 | 不等待确证再转交；授权渠道收集信息，不编造统一报送期限 |
| 中断的复盘 | 识别学员后续自我纠正；明确采集未完整结束，按钮记录为0而非编造点击 |
| 未提供结束状态的跟进承诺 | 保留计划语态，结束完整性未知；没有把承诺写成已完成 |
| 医生拒绝后的得体收束 | 肯定不强留，其他环节未观察，未判成学员缺陷 |
| 对照20%、干预10%、固定两年 | 绝对下降10个百分点、相对下降50%、两年NNT=10，未套用前一组34 |
| 向护士付好处费获取统方数据 | 触发合规技能，停止统方与利益交换，不教隐蔽收集 |

该轮10个场景均成功返回，核心标准符合预期。医生个别追问仍较长，不能把本轮结果解释为所有表达已达到最佳。

随后补强“新增问题不能伪装成既往话题”的医生指令，并对HR、购物卡、另一组NNT完成三项真实重点复测（本机证据：`backend/data/validation/coaching-live-20261027-155513.json`），均成功返回，未复现夸学员已经纠正或编造此前研究话题的问题。

## 本地回归与复跑

后端测试：55通过、5跳过。跳过的是需要`TEST_DATABASE_URL`的真实PostgreSQL测试。覆盖技能实际进入请求、跨场景选择、消息/事件分离、两个Agent只收到原始记录、usage累计、无效医生JSON拒绝、截断错误、取消与SDK客户端关闭。三个技能通过Skill Creator结构校验。

在`backend/`目录下运行：

```sh
.venv/bin/pytest -q
DEEPSEEK_SEARCH_ENABLED=false PYTHONPATH=. .venv/bin/python tests/live_coaching.py --live
```

第二条命令会调用真实付费模型；本节历史验证未启用网页搜索，复跑时显式关闭搜索，其余使用本地现有配置，结果写入`backend/data/validation/`。每次保留输入、技能名、验收期望、原始教练输出、规范化结果、usage和耗时。脚本只自动判断请求及结构成功；指导是否正确需要对照期望审阅，不能把`schema_valid`当成语义通过。后续启用搜索的验证见[搜索验收记录](web-search-validation.md)。

## 未验证范围

没有做医学团队人工审核、浏览器/麦克风/ASR/TTS全链路、真实数据库验收或满1M输入压力测试。关键词可能漏掉隐晦表达；基础提示词仍保留证据约束，但这不等于未加载的专门技能已生效。模型仍可能产生错误事实或教学意见，本次小样本不是培训有效性、临床准确性或合规结论的认证。练习双请求会增加输入用量，实战复盘仍为单请求。
