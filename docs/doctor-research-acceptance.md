# 医生检索到练习角色的验收

医生管理入口要求姓名、医院和科室。系统搜索公开资料、归档原文，匹配唯一身份后生成可编辑草稿；简称或任职差异造成自动匹配失败时，可在同一页查看候选姓名、医院、科室并确认后创建草稿，无需再次搜索。缺失或冲突的身份字段不能通过候选确认绕过。

两条入口共用角色生成逻辑，保留医院、职称、专业背景、逐项引文、来源版本和身份确认记录。自动匹配入口保留管理员输入的科室，原文中附带的科室时效说明仍保存在公开事实中。修改公开事实后，原检索证据只作历史参考。发布动作仍由管理员执行，不自动发布。

核对界面将事实与原文并排显示，并提供来源网页、原件类型、抓取时间和归档链接；未知发布日期与机构属性明确标记待核对。归档成功不代表原文支持模型结论，更不代表医学审核。两处进度读取最多自动重试三次，重试只读取已有任务，不重复搜索；耗尽后保留手动恢复入口。

医生发布后，用户端可搭配已发布药品自由练习。评分练习另需创建并发布场景及量表，管理页提供场景入口。

## 2026-10-31 验收范围

- 自动化回归：SQLite/PostgreSQL 检索草稿、来源证据、身份冲突、候选确认幂等、保存发布、自由练习与账号隔离；前端候选确认、断线重试上限、不重复检索和发布后导航。
- 实际模型及搜索：隔离目录检索“李小英 / 复旦大学附属中山医院 / 内分泌科”，获得三份归档和一个候选，成功生成草稿。一个医院页面返回 HTTP 403，任务如实显示部分完成并保留待核对项。
- 浏览器：在隔离管理端查看事实与原文，检查医院和职称回填，精简有日期限定的公开背景，确认后保存、发布，并检查发布后引导。
- 实际 HTTP：确认保存角色具有逐项证据和确认记录；搭配隔离虚构药品，确认自由练习预览使用该角色及编辑后的事实。

上述真实人物资料仅用于隔离软件验收，未写入生产医生库。验收不构成当前任职认证或医学审核；未新增真实语音设备验收。

## 部署与回退

没有数据库结构迁移。新增字段为已有 JSON 实体的附加信息；旧检索没有来源元数据时显示“待核对”。使用现有 CI/CD 和原生发布脚本，发布前备份，失败回退旧 release。服务重启会使现有登录会话失效，需重新登录。
