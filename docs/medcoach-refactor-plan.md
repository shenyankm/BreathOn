# 医药代表智能演练助手 v1：重构方案

本文描述目标架构、迁移顺序和验收方案，不表示功能、并发、供应商效果或真机体验已经完成或通过验证。产品要求与数据使用边界见 [PRD](medcoach-prd.md)。

## 架构与关键变更

沿用 React、Tauri、FastAPI、现有语音服务、PostgreSQL 和平台事务存储。一个前端构建分别提供 `/admin` 和 `/app`，保留旧链接和记录书签。首版复用有界检索和引用校验，不另加向量数据库或微服务。

1. 在现有登录身份上增加管理员名单及角色；HTTP、WebSocket、原件和导出均在服务端校验。代表只访问自己的记录和已发布共享资料；管理员可查看所有代表记录并留访问审计。本地免登录保留本机开发边界。
2. 将静态药品和政策目录幂等迁入后台，迁入材料标待核验，不自动获得医学审核状态。药品管理公司经营关系、受控分类与有依据的同类关系；政策文件和规则分开记录效力与审核状态。
3. 医生保持稳定身份，新增可审核的画像发布版本；公开事实逐项绑定来源，模拟设定分开。搜索结果只转换为草稿，同名、资料冲突或身份不明先由管理员确认。新画像只影响后续训练。
4. 统一平台审核资料与自动医学知识库的身份、版本、审核和适用性，后者作为已审核内容的派生检索产物。实时核验、场景检索与最终复盘使用相同的可用性规则；原始网页和自动摘要不因导入而成为正式证据。
5. 新增真实拜访日记及独立文件转写流程；已有演练案例继续标为模拟来源。资料、观察和模拟设定分层，审核决定产生新画像或场景草稿，正式发布后才进入共享训练。

## 数据与接口

| 接口或对象 | 目标变化 |
| --- | --- |
| `/api/auth/session` | 返回角色，角色由服务端配置决定 |
| `/api/catalog/{kind}` | 扩展药品、政策、医生及场景关联，代表只读取已发布内容 |
| `/api/research/jobs` | 目标对象、候选身份和结果转草稿；保留来源归档、取消及可选追踪 |
| `/api/visits` | 日记、来源类型、转写确认及脱敏正文 |
| 录音上传与转写 | 返回持久任务 ID，提供进度查询、取消及人工重试 |
| 审核与管理员记录接口 | 保存审核决定、理由、来源版本和草稿；管理员查看所有记录并审计 |
| 演练状态查询 | 区分进行中、结束处理中、已保存和中断 |

核心对象包括药品及同类关系、医生画像版本、政策规则版本、拜访记录、音频资产、观察和审核决定。演练启动固定药品、画像、规则、资料和量表版本；历史记录不跟随内容更新。资料撤回或失效后停止继续引用并提示原因。沿用 CAS，冲突返回 409，发布和任务提交具备防重复处理；旧场景产品文字保持兼容并逐步绑定药品 ID。

## 录音、任务和容量

录音单文件支持 MP3、M4A、WAV，最多 100 MB 和 30 分钟；客户端预检，服务端验证实际格式与时长。针对录音上传实施流式落盘及独立代理/API 限制，不扩大所有请求的内存缓冲。访问仅限本人、管理员和受控的供应商短时拉取链接，原音频和未脱敏转写存于独立私有卷，不进入数据库或长期备份；确认后的脱敏正文保存在平台数据库。

录音独立接入[豆包录音文件识别标准版](https://docs.volcengine.com/docs/doubao-voice/task-submission-http-1?lang=zh)，获取时间片段和说话人分离候选，人工确认角色。未确认身份的片段不得作为代表评价或医生事实。管理员可见原件，但只有经过校对、脱敏和审核的材料才进入团队训练。原音频与未脱敏转写按首次确认后 7 天或上传后 30 天中较早者删除；编辑不续期，同步删除临时副本和访问链接并留审计。

文件转写并行数初始为 1，独立于演练名额；任务持久化，重启后查询已提交任务或标记中断，不自动重复未知状态的收费请求。实时演练容量可配置，试点设 10，同一代表最多一场，第 11 场明确提示容量已满；保持单 API worker，名额占用至复盘和持久化结束。供应商配额与 10 路真实效果需要独立验证。

## Android 生命周期

在线 Tauri 外壳初始打开 `/app`。适配系统安全区、返回操作和权限说明，触控目标至少 44×44。切后台、锁屏或失去录音能力时停止采集；断网保留已接受内容，返回后查询状态，不静默恢复麦克风。服务端持续保存已确认的部分转录，进程或设备中断应保留可识别的中断记录；未收到保存确认不能显示成功。上传与转写根据任务 ID 恢复查看；首版不承诺离线启动或离线同步。

## 顺序与迁移

1. 保留已有未提交改动，明确医学知识库和 Android 基线及回归结果。
2. 完成角色、管理员可见范围、统一证据可用性及训练快照。
3. 建设药品、医生、政策、研究结果转草稿和审核发布。
4. 完成代表入口、后台数据接入、演练复盘及 Android 生命周期。
5. 实现日记、录音、脱敏、冲突审核和场景更新的闭环。
6. 执行迁移、恢复、真机与 10 场并发验收后试点发布。

保留现有已发布内容的原审核来源，为现有医生建立初始画像版本；不重写历史会话、归属或评分。迁移采用版本化脚本及完整备份恢复演练，重复执行不重复导入。SQLite 与 PostgreSQL 均须验证，资料及其原文版本一并保护。

## 测试与发布门槛

- 权限：代表直调管理入口被拒、不能查看他人数据；管理员可访问既定范围，访问留痕；文件、WebSocket、导出和页面深链均覆盖。
- 目录：组合筛选、同类关系依据、停用、新版本、同名医生、职务变更、研究来源不足、政策未来生效/失效和适用范围。
- 证据：未审核或已撤回材料不能进入三条正式判断链路；缺证据时维度与总分留空；历史快照不被新资料改写。
- 日记与录音：授权、格式伪装、超限、空音频、说话人错分、敏感内容、取消、重复提交、失败和重启；首次确认后 7 天及上传后 30 天取较早时间，修改不续期，副本和短链清理。
- 反馈：真实拜访、访后自述和演练案例来源隔离；单次感受不变成真人永久性格；未经审核不进入共享训练。
- 并发：10 个不同账号同时完成演练及保存，第 11 场受到明确限制；转录、费用、画像和资料版本不串线；验证断线、取消和复盘阶段占位。
- 真机：录音权限、扬声器、有线和蓝牙耳机、打断、来电、锁屏、切后台、网络切换、系统杀进程和文件操作；Web 自动化不能替代真机验收。
- 迁移：SQLite 与 PostgreSQL 行为一致，重复运行幂等；备份恢复后历史记录、资料及来源可读。

试点记录完成率、延迟、费用、审核采纳率和同条件重练变化；真实医疗与法规内容须由具备职责的人员审核，不能将测试通过等同于医学或法律结论已被认证。
