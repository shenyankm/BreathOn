## 使用路径

1. 启动现有后端和前端，配置真实服务密钥。在仓库根目录执行 `uv run --directory backend python -m tools.prepare_training --apply`，导入已核对来源的说明书、虚构医生、七维量表及首访基线。脚本核对 PDF 哈希和实际页文，不覆盖同名但不同的配置，不自动发布分享导入的草稿。
2. 在「训练管理 → 训练场景 → AI 生成拜访场景」选择已发布医生、评分标准及有效资料，填写目标、情境和难度。生成结果保留资料版本、原文引文、模型、用量、耗时和费用估算，先进入草稿；核对背景、异议、完成标准后保存、发布。
3. 打开「开始演练」，确认推荐场景并点击「开始练习」。演练方式默认带教练练习，需要时展开切换；资料与评分依据、训练环节按需展开。复盘记录保留学员原话、资料页码、问题原因、改进动作和参考表达；未观察或无依据的维度保持未评分。
4. 从复盘建立重练，自动带入原场景、环节和演练方式。创建计划和启动时均检查医生、场景和资料版本；对比还要求环节、练习/实战模式、量表指纹、模型和评价版本一致。条件变化会说明原因并停止给出进步差值。
5. 在记录中选择一条完整学员原话提炼案例。原话单独保留；默认回应与理由对应所选片段，可编辑并确认边界。修改后恢复待核对状态，未保存修改时不能点击复用；确认后可用于新场景、导出 JSON 或 Markdown。
6. 在「经验案例」导入案例，或通过场景模板分享完整配置。导入生成新的本机标识，外来案例保留未核实来源标记，医生、资料、量表和场景进入草稿，不继承审核或专家校准状态。重复导入打开已有配置。
7. 在「复盘记录」先查看原话和待重练项；需要汇总时展开列表之后的「查看训练变化与服务用量」，查看近 7/30/90 天的同条件反馈、次数、已记录时长和实际服务用量。在「训练管理 → 用量计价」核对价格依据；后续修改只影响新演练，旧记录保留启动时的价格快照。

培训师点评、留痕改分和专家校准沿用现有入口。轻量使用通过文件分享完成，不引入账号、部门或批量任务。

金额用 Decimal 计算，CNY 与 USD 分别累计。未返回输入/输出用量、缺少价格、采集或分析未完整结束时保留“未完整计价”，不把缺失项视为免费；估算不等于账户账单。

交叉代码检查复现并修复：ASR 对同一片段修正文案后，旧提示仍被当作当前提示且不重新生成；较早片段仍未定稿时可能提前分析；发送修正转录期间旧模型结果可能抢先写入。现在立即使依赖旧原话的提示失效，保留已送达医生原话，等待转录定稿后重新生成，并在异步发送前使旧请求失效。新增 4 个确定性回归用例覆盖这些路径。

独立内容复核发现旧提示偶尔把开场、澄清和收尾统称为重复回答。首次补充跨句核对约束后，analysis 已区分各轮，但第四轮 fluency 仍误称“四句都在讲原则”。继续限定 fluency 的分析范围后，用同一真实四轮转录和相同版本资料进行两次真实模型回放，均未再把开场算入后续三次未答复；结果保留于回放报告（本机证据：`backend/data/validation/multiturn-fixed-20261029/real-transcript-replay.json`）。模型仍会作主观概括，措辞及评分没有全面质量保证。首组三模式测试中，练习的最终转录到医生/教练文字耗时约 **5.9–16.2 秒**，并非即时返回。
