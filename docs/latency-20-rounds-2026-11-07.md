# 延迟与首字 20 轮优化 · 2026-11-07

从干净的 `main` / `f7c283512106129469d12626f1a90fd26f23c405` 建立新基线，完成 **20 个独立候选，最终保留 13 个、回退 7 个**。没有复用以前实验的轮数或测量结果。新增依赖为零，未提交或部署。

本轮优化 SDK 首个模型文本增量、完整医生文本、ASR 首个文本事件和 TTS 首个 PCM。所有供应商均由明确的合成响应或本机 WebSocket 服务替代；没有读取 `.env`、调用收费供应商或使用真实会话。结果不代表真实模型推理或识别质量。

## 关键结果与时间起点

- **SDK 首个文本增量：80.43 → 12.31ms，下降 84.7%**。受控 SSE 在首块后延迟发送尾块；解除整包缓冲后，Pi 能在尾块到来前读到增量。增量包含 JSON 前缀，不是用户已经看到完整医生回答。
- **并发额度为 1 的完整医生文本：85.49 → 14.60ms，下降 82.9%**。医生请求先取得额度；教练仍完成、计量仍保留。无排队对照未观察到同等幅度提升。
- **本机真实 SQLite 与 20 份资料：回应入口到完整医生文本 526.26 → 470.22ms，下降 10.6%**。其中“开始思考”后阶段为 123.90 → 68.29ms（下降 44.9%）。前一个口径包含原有约 400ms 等待；不把阶段收益当成总链路收益。Pi SDK、资料检索和版本验证实际执行，模型内容为合成结果；TTS 和首字后的检查点写入不纳入这个首字指标。
- **ready 后首个 ASR 文本事件：225.25 → 112.04ms，下降 50.3%**。使用真实本机 WebSocket 和 20ms PCM 帧节奏，识别服务器只验证接收协议并返回固定文本；这是分包/传输首字指标，没有测真实识别推理。
- **模拟通知写回等待的 TTS 首 PCM：30.37 → 16.44ms，下降 45.9%**。这是本机首音频包，不是设备首次可听播放，也不代表供应商合成速度。

ASR 首包从 200ms 调整为 100ms，后续仍为 200ms；未改采样率、20ms 客户端帧、VAD、二遍识别或回应等待。100–200ms 分包依据为[火山引擎接入必读](https://docs.volcengine.com/docs/doubao-voice/access-must-read-1-1?lang=zh)，当前接口及二遍识别参数核对[实时语音识别 API](https://docs.volcengine.com/docs/doubao-voice/bidirectional-streaming-automatic-speech-recognition-websocket?lang=zh)（2026-11-07）。未启用可能影响准确率的首字加速参数。

## 实验方法

- Node.js v22.23.2，macOS arm64，同一锁文件依赖。初始与候选源码分别冻结到隔离目录，资源与依赖指向同一版本。基线源码归档和 SHA-256 保存在 manifest 中。
- 每轮目标负载按 `ABBAAB` 启动 6 个独立 Node 进程，小负载按 `ABBA` 启动 4 个。每个进程先预热一次，再执行 5 批；微小函数每批执行多次并取均值，交互路径每批一次。汇总值为进程中位数之中位数，批次前显式 GC。
- 保留门槛：目标首字/阶段耗时至少减少 5%，3 组配对至少 2 组减少 5%，大小负载输出分别等价。小负载退化超过 15% 时，绝对差须小于 0.5ms；完成耗时退化超过 10% 时，绝对差须小于 1ms。第 18 轮输出预算还必须经过质量验证，本轮不具备该证据，直接回退。
- 全部性能测量串行运行，没有同时运行本任务的构建或测试；机器不是独占，未绑核。指标是这些输入下的本地测量，没有构造请求 p95/p99 或线上 SLA。
- 第 3–5 轮为独立 I/O 人工延迟的控制场景，用于验证并行等待；不是在声称本机数据库必然有相同等待。最终另测真实 SQLite/资料路径。
- 输出校验排除时间戳和随机响应 ID，核对实际文本、结构化结果、已响应标识或完整 PCM；时间字段单独保存。PCM 在基准及回归中均逐字节对照，没有用删帧降低首字。

## 真实存储控制与最终回退

第 14 轮并行参考检索在模拟独立 I/O 中先得到约 74.7% 的收益。追加真实 SQLite、20 份长资料和四产品处理，按 `ABBAAB` 六进程测量后，只有 **270.105 → 266.911ms（1.18%）**；三组配对为 1.02%、-1.27%、1.18%，未达到门槛。因此最终恢复串行产品检索，不保留这项并行化。

初稿保存在 `round-14-initial.json`，真实控制为 `reference-control.json`。最终参考路径仍因第 13 轮省去未使用的审批计算而有收益；不能把它归功于已回退的并行化。驱动脚本已补入该真实控制门槛。

最终全部综合复测在这次回退后重新执行。回退前的复测保留为 `overall-before-reference-control.json`，不作为最终结果；追加测量不计为额外候选。

## 正确性与验收

- 新增 8 项延迟定向回归，覆盖首增量先于尾块、消费期间的并发额度、未消费响应取消、断流不重放、医生优先、无效 JSON 不发布、16 条输入窗口与全部历史响应标识、版本失效阻止发布，以及技能文件编辑/缺失/恢复。
- 另增真实 WebSocket ASR 分包回归，覆盖首包 3,200 字节、后续两个 6,400 字节包、1,920 字节尾包、静音零填充和总计 0.56 秒的计量。完整输入与输出 PCM 字节一致。
- PostgreSQL 回归扩展 metadata 查询：默认完整读取仍保留原文，省页读取仅省略 `pages`；SQLite 的旧版本、退役资料和重复编号不同版本仍拒绝。
- 后端 **78/78**、前端 **183/183**、训练浏览器 **10/10**，零失败；管理端 E2E **22 通过、6 跳过、零失败**。跳过为 5 项收费供应商和 1 项未连接 Android WebView。后端、Web、Android 前端构建通过；lint 零错误、2 条既有 Fast Refresh 警告。详见 [validation.json](evidence/latency20-20261107/validation.json)；包含独立 PostgreSQL 容器，运行后删除。
- 新增分包测试初次将 28 帧瞬时发送，触发既有的 16 帧接收队列保护。测试改为真实的 20ms 输入节奏后通过；未放宽服务端队列或音频限速。初次失败日志保留为 `backend-tests-initial.txt`。
- 检查点写入、完整 JSON 验证、医学凭据复核、资料版本/状态与账号隔离继续执行。模型响应只对 SDK 解除整包等待，用户可见医生文字仍等待完整 JSON、结构及资料校验。
- 响应流在 EOF、取消或错误后释放额度；部分字节已经暴露后不自动重放请求。预响应的状态码重试和上限保留。
- 所有材料索引限于本次验证；技能缓存每次核对 mtime/ctime/size，编辑或失败后的恢复会重新加载；没有给医学资料或审核状态设置跨请求缓存。
- 只应用 13 个保留补丁即可重建最终全部前后端源码的 SHA-256 集合；此前已提交的清理、学习闭环和性能改动保留。
