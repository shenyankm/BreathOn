# 医药代表智能演练助手 v1：产品需求

> 需求／方案基线：保留需求来源与当时设计，不代表全部已实现。客户端拆分、课程与管理功能已有后续调整；当前实现见[功能范围](platform-completion.md)和[架构](architecture.md)。文中的旧 `/app` 方案不再是部署入口。

本文是已确认的目标设计和验收依据，不表示各项功能已经实现或通过验收。实际实现与运行状态以代码、测试和发布记录为准。

## 目标与范围

面向单公司建设管理后台和代表 Android 端，将公开资料、训练、复盘和前线反馈连接成可审核的闭环：公开资料检索 → 画像与知识审核 → 语音演练 → 复盘与重练 → 真实拜访记录 → 冲突审核 → 更新训练内容。

首版设管理员和代表两种角色，管理员兼任审核；管理员可查看全部代表的日记、录音和演练记录，代表之间隔离。正式训练采用审核发布的内容，管理员查看不等于允许纳入团队训练。以 10 场同时语音演练为验收目标，使用现有 Tauri Android 技术路线。

自由练习先选药品，医生候选自动限定为科室对口的已发布角色。药品与医生通过科室形成多对多关系；更换药品自动清空不匹配医生，没有候选时不能开始。这里只判断科室与药品领域对口，不判断个人处方权限。

目标是提高专业拜访、证据表达、需求澄清和合规沟通能力；不以处方量或采购承诺评价代表。首版不建设多企业租户、模型微调、考试认证、销售 CRM、排行榜、离线演练或真人声音克隆。产品价值需通过试用验证，不因演示成功推断真实效果。

## 管理后台

入口为 `/admin`，侧栏包括药品、医生、政策、训练内容、审核队列、代表记录和系统设置。列表提供搜索、组合筛选、状态和更新时间；详情展示来源、审核记录与版本差异。

### 药品

- 管理本公司产品和同类竞品，支持新增、编辑、资料导入、审核发布和停用。保存通用名、商品名、别名、上市许可持有人、生产企业、经营关系、治疗领域、疾病、靶点/机制、剂型、获批地区和适应症；经营关系不能仅由生产企业推断。
- 分类词表由管理员维护。支持按归属、治疗领域、疾病、机制、剂型、地区、发布状态、资料完整度筛选；同条件多选取并集，不同条件取交集。
- 同类关系区分同机制及同适应症/治疗位置，记录理由和依据，推荐候选经管理员确认才生效。对比页并列获批范围、人群、研究、安全性和证据版本；缺失标记未知，不自动推断疗效优劣或可替代性。
- 说明书、临床研究、指南、医保和内部资料分别标注类型，产品展示信息与正式训练依据保持清晰关联。

### 医生

输入姓名和可选医院、科室，系统搜索候选身份；管理员确认目标后归档公开资料并生成画像草稿，审核发布。支持医院、大学、专业协会、公开论文与会议信息；同名、医院不明、职务冲突或作者归属不确定时停在身份确认或待核对状态，不编造事实。

画像保存职业背景、专业方向、公开学术关注点、来源和核验时间。训练难度、交流节奏、情绪、追问方式独立标为模拟设定，不宣称是真人的固定性格。已发布画像修改形成新草稿，发布后只影响新演练，历史会话使用原快照。支持手动更新和管理员主动开启的每日追踪；新发现进入审核队列，检索失败保留上版。

### 政策与训练规则

支持官方链接归档与 PDF、Word、文字导入。文件保存标题、机关、文号、发布/施行日期、地域或机构、类别、效力状态、替代关系和原文版本；文件效力与内部审核状态分开，区分征求意见稿、待施行、有效、失效和待核实。

训练规则绑定具体条款、适用场景、风险级别、判断示例和提示动作。风险输出包含代表原话、解释、条款与来源，不能由模型直接认定违法。普通风险提示；明确且经过审核的高风险规则可暂停演练，仅凭关键词或不确定判断不能自动终止。新文件进入审核队列，不因网页变化自动废止旧规则。

[《医药代表管理办法》第二十四条](https://www.gov.cn/gongbao/2026/issue_12826/202606/content_7073631.html)涉及误导用药、夸大或者误导疗效等行为；参考截图中的概括不是可直接引用的逐字条款。具体规则须按原文审核。

### 场景、审核与记录

场景绑定主药品、可选竞品、医生画像、适用政策、有效资料和评分量表。保留完整拜访和分环节训练，覆盖首访、跟进、时间紧张、证据质疑等情境。

审核队列处理资料、医生画像、政策规则及拜访日记产生的训练候选，展示修改前后、证据、冲突和理由。管理员可按代表、时间、医生、药品和状态查看演练与拜访记录并点评。首版账号使用配置方式管理，显式设置管理员名单，不增加组织树或账号管理平台。

## Android 代表端

底部导航为演练、拜访日记、资料和我的。演练支持选择药品、医生、场景与模式，显示目标后开始语音；对话页明确录音状态，固定静音和结束操作，来源可展开。资料页只读已发布内容和来源；我的页面提供个人记录、重练和退出登录。

辅助练习提供逐轮教练、医学和合规提示；独立演练主要在结束后复盘，明确的高风险训练规则仍可暂停。模拟医生可根据本场表现调整追问和态度，不回写为真实医生属性。

复盘默认医学准确性 40%、合规性 30%、沟通技巧 30%，展示评分依据、关键原话、最多三条优先建议和重练入口。缺证据或未观察维度显示无法评价；维度不完整时不生成总分，不补造建议。

## 拜访日记与真实录音

访后自述或文字：选择医生、日期及药品 → 口述或输入 → 校对 → 确认保存。真实录音：登记录制及使用授权 → 上传 → 转写和说话人分离 → 人工确认角色 → 校对和脱敏 → 生成拜访摘要及训练候选。

- 首版支持 MP3、M4A、WAV，单文件不超过 100 MB、30 分钟；客户端预检，服务端复验。导入前说明管理员可见范围和第三方 ASR 处理；不提供隐蔽录音或后台持续录音。
- 自动分离仅产生说话人编号，由用户确认医生、代表和其他角色；未知片段不能计入代表评价或医生事实。真实拜访、自述和 AI 演练案例分别标记来源。
- 自动识别敏感信息并辅助删除；人工确认脱敏后才能提炼或提交共享训练审核。原音频、未脱敏转写和脱敏正文分别管理；文字脱敏不意味着音频脱敏。
- 原音频及未脱敏转写按首次确认转写后 7 天、上传后 30 天中的较早日期删除；修改转写不续期。同步清理临时副本、访问链接及缓存，保留删除审计。音频使用独立私有存储，不进入长期备份；保留已确认脱敏正文与采纳记录。

## 可信知识与冲突处理

公开事实绑定原文来源、版本和片段，审核后用于画像背景与评价依据；拜访观察保存时间、情境、原话和主观感受，只能产生待审经验；忙碌、质疑和难度属于模拟设定，不能声称是真人事实。

系统发现冲突后并排展示现有内容、新来源、时间及原文定位；管理员选择采纳为事实更新、仅用于模拟情境、待补证或拒绝并记录理由。转载不算独立来源，多人反馈也不能投票证明医学事实。采纳结果先产生新草稿，发布后才影响后续训练；撤回资料时标记受影响内容并停止引用。正式医学判断必须回到已审核、当前适用的原文版本与片段。公开个人资料处理应支持更正与删除。[个人信息保护法](https://flk.npc.gov.cn/detail?doc=4dfcc01e1c40ad4a4d16efe19a2db14a870f76ae3a722c30e82a12b86e4acdaf)

## 验收与衡量

验收需覆盖：角色和跨代表隔离、药品关系与筛选、同名医生和来源不足、政策效力和语义误判、未审核证据不可用于正式评分、音频格式/超限/错分/失败与删除期限、经验来源区分和审核门槛、10 场并发及第 11 场限流、真实 Android 设备音频与网络生命周期、数据库迁移和恢复。

试点记录演练完成率、回复及复盘耗时、服务费用、审核采纳率和同条件重练中的问题变化。这些用于改进，不直接视为培训成效。详细技术和测试计划见 [重构方案](medcoach-refactor-plan.md)。
