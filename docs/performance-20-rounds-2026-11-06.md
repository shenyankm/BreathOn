# 20 轮性能优化 · 2026-11-06

完成 20 次候选实验，保留 14 次、撤回 6 次；新增 12 项性能与边界回归测试。所有保留候选在大数据和小数据控制组上输出等价。没有把重复测量算成优化轮次。

## 基线与方法

- 基线是本轮开始的后端源码快照，包含前一轮已在工作区中的状态机修复；Git 基点 `e26d97d3bb261c0b3bd822d1370f699b3df0c5ac`。`evidence/perf20-20261106/baseline.patch` 保存基点到该快照的差异。
- Node v22.23.2、arm64、macOS-27.0.1-arm64-arm-64bit；相同机器、依赖和合成数据。程序不加载应用 `.env`，模型和语音不调用收费服务，数据在临时目录，PostgreSQL 使用独立临时容器。
- 每轮一个独立候选：冻结之前/之后源码，按 ABBAAB 顺序启动隔离 Node 进程，每版 3 个进程；小数据控制组 ABBA，每版 2 个进程。预热 3 次，随后每进程 9 个测量批次；单批自动选择重复次数，表格取每进程中位数的中位数。基准串行运行，不和测试或构建同时执行。
- 接受门槛为稳定且至少约 5% 的目标场景收益、输出等价、关键失败语义正确。小控制组低于 0.001ms 的绝对波动按非实质差异处理，并保留原始值。
- 原始 `elapsed_ms` 和 `cpu_us` 在逐轮 JSON 中；`p95_ms` 是批次均值样本的 p95，不是线上单请求 p95。没有据此推算整机内存、冷盘吞吐量或线上并发容量。
- 逐轮补丁链已验证：从 Git 基点应用基线补丁，再按顺序仅应用保留补丁，能重建最终 `backend/src` 的 SHA-256。源码、基准和锁文件哈希见 [manifest](evidence/perf20-20261106/manifest.json)。

## 综合复测

在所有轮次结束后，重新比较本轮起始快照与最终版本。ABBA 隔离进程，每版 2 个进程、每进程 9 个批次，所有输出哈希一致。

| 综合复测场景 | 起始快照 ms | 最终版本 ms | 耗时减少 |
| --- | ---: | ---: | ---: |
| 24 份 × 24 页检索 | 19.810 | 5.113 | 74.2% |
| 2,000 句 ASR 快照（隔离存储 I/O） | 12.463 | 1.691 | 86.4% |
| 12 份审核资料与 18 个同源来源 | 218.953 | 46.273 | 78.9% |
| 400 份 JSON 记录读取 | 23.461 | 11.820 | 49.6% |
| 400 条发言、1,200 条核验的复盘校验 | 1.124 | 0.056 | 95.0% |

以上属于本地热点处理延迟。ASR CPU 场景用存储桩隔离查找开销；真实检查点另在第 4 轮执行 fsync/目录同步，未保留破坏持久性的优化。文件读取由预热调用加热文件缓存。第 11 轮数据为 24 份每份约 40 万字符的资料；第 12 轮为同一事务内 150 次实体读取；第 17 轮为 64,000 字节 PCM 的编码及 640 字节控制组；第 18 轮一次测量包含 80 个语音窗口；第 20 轮为 24 句、每句 6 个引用、12 个不同证据块。

## 复现

基准入口 `backend/benchmarks/performance-twenty.ts` 接受 `--root <backend源码目录>`、`--case`、`--small`、`--samples`。源码目录需具有对应 `resources`、`migrations`、`parsers` 和相同依赖的 `node_modules`；不要复制应用凭据或业务数据。可从 Git 基点和保存的补丁重建任意轮次，撤回补丁只用于临时对照。

```sh
node --experimental-transform-types --expose-gc backend/benchmarks/performance-twenty.ts --root /absolute/snapshot/backend --case retrieve --samples 9
node --experimental-transform-types --expose-gc backend/benchmarks/performance-twenty.ts --root /absolute/snapshot/backend --case retrieve --small --samples 9
npm --prefix backend test
# 使用独立可清空的本地 PostgreSQL 设置 TEST_DATABASE_URL，再跑后端测试。
npm --prefix frontend test
npm run build
npm run build:android
npm run lint
```

工作负载名称及参数、原始结果、源码哈希均保存在逐轮 JSON 中。综合对照也可以用同一命令分别指定起始和最终源码目录。
